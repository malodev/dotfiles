### Summary
Refactored `index.ts` so the `pi.registerCommand("forge", ...)` handler is a thin integration shell that performs **parse → delegate → append → derive → render** only. Business transition logic was extracted out of the inline handler into standalone command-handler functions and V2 services.

### Key Changes
- **Extracted `handleExecuteCommand`** — handles execution routing, including planning resumption and paused→resume transitions, all delegated to V2 command services (`executeCommandService`, `resumeCommandService`).
- **Extracted `handleBlockerCommand`** — encapsulates all blocker sub-commands (list, diagnostic, retry, force-unblock, patch-validation, resolve) while keeping the main handler thin.
- **Extracted `handlePlanningResumption`** — moves interrupted-planning and complex-checkpoint resumption logic out of the execute handler body.
- **Thinned the `pi.registerCommand` handler** — reduced from ~500 lines of inline orchestration to a ~100-line router that loads the snapshot and calls the appropriate handler.
- **Removed inline V1 state mutations** in `execute` and `resume` handlers (e.g., `state.status = "executing"`, `persistState` calls). The shell now appends V2 events and lets snapshot derivation update state authoritatively.
- **Removed redundant `pendingHumanIntervention` guard** in the execute handler — `executeCommandService` already enforces this via `canExecute`.
